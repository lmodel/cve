# Datasets

* [cve LinkML schema](cve-linkml-schema.md) - The LinkML model of the CVE Record Format 5.2.0, `src/cve/schema/cve.yaml` (schema id `https://w3id.org/lmodel/cve`): an umbrella that holds only the tree root, `CveRecordRoot`, over the modules `cve_record` and `cve_cvss`.
* [Record module](record-module.md) - `src/cve/schema/cve_record.yaml`, the module that models a CVE record: its metadata, the assigning authority's container, other publishers' containers, products and versions, references, metrics and the tag lists.
* [CVSS module](cvss-module.md) - `src/cve/schema/cve_cvss.yaml`, the module with the score objects `CvssV20`, `CvssV30`, `CvssV31` and `CvssV40`, FIRST's property names as keys and each severity's score band. It imports only `linkml:types`, so that lmodel/nist-nvd can vendor it alone.
* [Generated artefacts](generated-artefacts.md) - What `just gen-project` and `just gen-doc` generate from the cve schema: the projections in `project/`, the Python models in `src/cve/datamodel/`, and the merged schema in `docs/schema/`. None is edited by hand.
* [Example data](example-data.md) - The examples `tests/test_data.py` checks: a valid example of each class, a counter-example for each constraint, and the rules no generated JSON Schema states, in `tests/data/valid/`, `invalid/` and `problem/`.
* [Sample of real records](real-record-sample.md) - The pinned sample of 421 real CVE records from cvelistV5 in `tests/data/cvelist/manifest.json`, with a small extract copied beside it, which `just test-cve-records` validates unchanged. No record departs from the schema.
* [Copy of the upstream](upstream-copy.md) - `upstream/`, the files of `CVEProject/cve-schema` at the tag `v5.2.0`, each pinned by its git object hash: the format's JSON schema, its tag lists, its CVSS schemas, the example records and the licence.
* [Mapping term list](mapping-term-list.md) - `tests/upstream/mapping-terms.txt`, the classes and properties of Dublin Core, schema.org and the SEPSES CVE and CVSS ontologies, which `scripts/extract_mapping_terms.py` writes from each vocabulary's pinned file and `tests/test_mappings.py` holds each mapping to.
* [Neighbours' adapt copies](neighbour-copies.md) - The seven released lmodel adapt copies in `tests/neighbours/` (slsa, github-actions, in-toto, oscal, spdx, stix and uco), each pinned by its SHA-256, against which `tests/test_schema_rules.py` holds this schema's copy apart.
* [The schema's adapt copy](adapt-copy.md) - `.lokf/schema/cve.yaml`, the copy `just lokf-adapt` writes from the schema so that it sits beside LOKF's `lokf.yaml`: rooted on `CveRecord`, with eleven keys that LOKF also defines renamed with a `cve_` prefix, each keeping its IRI.
* [The upstream's basic example, as a concept](example-published-record.md) - The format's own basic example record, `upstream/schema/docs/full-record-basic-example.json`, written as a concept of type `CvePublishedRecord` in the adapt copy's keys. It shows that the domain schema admits a record as a concept. CVE-1900-1234 is the upstream's made-up identifier.
